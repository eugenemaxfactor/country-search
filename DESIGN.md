# Country Search — Design Notes

## Общая структура

Приложение разделено на небольшие части с одной ответственностью:

- `debounce.ts` управляет только задержкой вызова функции;
- `searchCountries.ts` выполняет HTTP-запрос и обрабатывает HTTP-статусы;
- `mapCountryResponse.ts` преобразует данные API в модель приложения;
- `classifySearchError.ts` различает типы ошибок;
- `createCountrySearchHandler.ts` координирует debounce, отмену и поиск;
- `createApp.ts`, `createCountryCard.ts` и `main.ts` отвечают за интерфейс.

Логика запросов и преобразования данных не зависит от DOM и тестируется без
реальной сети.

## Отмена устаревших запросов

При каждом изменении input текущий `AbortController` отменяется сразу, до
ожидания debounce. После задержки для нового запроса создаётся новый controller.

Порядок событий:

1. Пользователь изменяет текст.
2. `handleSearchInput` вызывает `abort()` для активного запроса.
3. Новый текст передаётся в `debounce`.
4. После задержки создаётся новый `AbortController`.
5. Новый signal передаётся в `searchCountries` и затем в `fetch`.

Отмена до debounce важна. Если ждать 300 мс и отменять запрос только перед
следующим `fetch`, старый ответ может успеть прийти во время ожидания и показать
неактуальные данные.

Флаг вида `isLatestRequest` не использован. Такой флаг только игнорирует уже
полученный ответ, но не отменяет сетевую работу. `AbortController` действительно
останавливает устаревший запрос, что видно в Network panel браузера.

## Выбор задержки debounce

Используется задержка 300 мс. Она достаточно короткая, чтобы интерфейс ощущался
быстрым, и одновременно не отправляет запрос после каждой введённой буквы.

Без debounce приложение создаёт много лишних запросов при быстром вводе. При
слишком большой задержке, например 1000–1500 мс, поиск визуально ощущается
медленным даже при быстром ответе API.

Функция `debounce` не зависит от конкретного значения задержки. Координатор
получает delay через параметр, поэтому в тестах и приложении можно использовать
разные значения.

## Таймаут и обработка ошибок

`searchCountries` объединяет два сигнала:

- signal пользовательской отмены;
- `AbortSignal.timeout(10_000)`.

Для объединения используется `AbortSignal.any`. Это позволяет одному `fetch`
реагировать и на новый ввод, и на отсутствие ответа сервера.

Ошибки разделяются следующим образом:

- HTTP 404 означает отсутствие совпадений и преобразуется в пустой массив;
- `AbortError` означает намеренную отмену и не показывается пользователю;
- `TimeoutError` означает, что сервер не ответил за отведённое время;
- `HttpError` хранит неуспешный HTTP-статус, отличный от 404;
- остальные ошибки считаются сетевыми или неизвестными.

При настоящей ошибке интерфейс сохраняет введённый запрос и показывает кнопку
Retry. Кнопка повторяет поиск по текущему значению input.

## Сложность `mapCountryResponse`

Функция один раз обходит:

- массив языков длины `L`;
- массив валют длины `C`;
- массив границ длины `B` при создании копии.

Временная сложность: `O(L + C + B)`.

Дополнительная память: `O(L + C + B)`, потому что функция создаёт новые массивы
языков, валют и границ. Исходный объект API не изменяется.

## Принципы чистого кода

### Одна ответственность

- `searchCountries` не создаёт UI и не решает, когда отменять запрос;
- `mapCountryResponse` не выполняет сеть и не работает с DOM;
- `createCountryCard` только создаёт представление одной страны.

### Понятные имена

В коде используются имена `activeController`, `timeoutSignal`,
`normalizedQuery`, `rawCountries` и `formattedCurrency`. Они описывают роль
значения без дополнительных комментариев.

### Небольшие функции

Основные действия разделены между `debounce`, `searchCountries`,
`mapCountryResponse`, `classifySearchError` и `createCountrySearchHandler`.
Каждую часть можно проверить отдельно.

### Чистые функции и неизменяемость

`mapCountryResponse` создаёт новый объект `Country` и новые массивы. Входной
`RawCountryResponse` не изменяется, что подтверждается отдельным тестом.

### Явные состояния интерфейса

Интерфейс отдельно показывает initial, loading, empty, success и error.
Динамические элементы создаются через `document.createElement`; `innerHTML` и
`insertAdjacentHTML` не используются.
